# Canvas engine: JS API

The engine is a WASM module (`engine/pkg`, built by `engine/build.sh`) that draws resolved boards with vello on WebGPU. One `Engine` owns one `<canvas>`. Everything else on the page (selection, hover, titles, widgets) stays DOM and asks the engine for geometry.

```js
import init, { Engine } from '/pkg/canvas_engine.js';
await init();
const engine = await Engine.create(canvas);
```

Working example: `engine/dev/dev.js` (the engine-vs-DOM dev page).

## Coordinates

- **World**: canvas units. A board at `(x, y)` has its root's top-left there.
- **Screen**: CSS px relative to the canvas's top-left: `screen = world * z + (camX, camY)`. Same convention as the page's `cam {x, y, z}`.
- Device px are `screen * devicePixelRatio`; the engine handles them.

## Inputs from the Canvas server

- `GET /api/scene?file=<file>&id=<boardId>` returns one board, resolved: instances expanded (path ids like `Inst/Child`), `$variables` resolved for the active theme, disabled nodes dropped, image URLs rewritten to `/asset?p=…`, icons turned into SVG path data (`iconShapes`). Payload: `{ version, id, x, y, key, revision, root, fonts: [{family, weight, style, url, fallback?}], images: [url], warnings }`.
- `GET /api/fonts/file?family=&weight=&style=[&file=<file>][&subset=<name>][&text=<hex,hex>]` returns plain TTF/OTF bytes (WOFF/WOFF2 unpacked). Order: the document's own `fonts`, then for web families the exact WOFF2 the page's Google Fonts stylesheet gives Chrome (variable font, one unicode-range `subset`; skipped for system families and when `CANVAS_WEB_FONTS=0`), installed fonts. `family=system-ui` is macOS's SF Pro (`SFNS.ttf`). `text` cuts Apple Color Emoji down to those code points (an sbix font of a few KB instead of 190 MB). Response headers `x-font-weight` (`0` = a variable face: use its own `wght` axis), `x-font-style`, `x-font-source`. 404 when nothing matches.
- Scene `fonts` lists every file the board's text needs, in fallback order: per family the Google subsets its text touches (else the document's or installed file), `system-ui`, then the platform font CoreText would use for characters neither has (Lucida Grande for Hebrew, Geeza Pro for Arabic, Apple Color Emoji, ...). A family split over several files carries a tag: `Inter\u001f0:latin`, `system-ui\u001f1:Lucida Grande`. Register each entry under its `family` string as given; the engine chains tagged faces after the plain family in tag-number order.

## Engine

| Call | Returns | Notes |
|---|---|---|
| `Engine.create(canvas)` | `Promise<Engine>` | Requests a WebGPU device. Sizes the drawing buffer from the canvas's CSS size × `devicePixelRatio`. Resolves before vello's pipelines exist: they are built in a task right after (0.6 s cold in WKWebView), so start it in parallel with the first doc fetch. `frame()` draws the background until they are ready. |
| `registerFont(family, weight, style, bytes)` | faces added (0 = already had it) | `bytes`: `Uint8Array` of TTF/OTF. Pass the face's `x-font-weight` / `x-font-style` (they act like `@font-face` descriptors; `0` / `""` uses the file's own). Boards using the family are laid out again. Register a board's fonts, including the `system-ui` fallback, before `setBoard` to avoid a second layout. |
| `registerImage(url, data, width, height, opaque?)` | — | `url` exactly as in the scene's image fills. `data`: an `ImageBitmap` at full size (the engine keeps it: do not `close()` it), or straight-alpha RGBA8 `Uint8Array`/`Uint8ClampedArray` of `width*height*4` (kept on the JS side). Nothing is copied into WASM memory: each use of the image draws a mip level for its on-screen size (the original halved until it is the smallest copy at least that big, made by 2x box steps), decoded on demand into a GPU texture; one texture holds at most 2048 x 2048 px, and an opaque image that needs more is drawn from 512 px tiles of the part in view (an image with transparency stays one texture). `opaque`: `true`/`false` when the caller knows whether the image has no transparency (a JPEG; every pixel checked in a worker); left out, the engine reads every pixel itself the first time the image needs tiles, about 2 Mpx a step inside the frame's 8 ms decode box, and draws it whole until it knows; boards far from view give their levels back; idle levels are evicted under `setImageBudget`. Boards drawing it are repainted. |
| `unregisterImage(url)` | `bool` | Frees an image `registerImage` took: every board gives up its levels, the GPU textures are freed and the engine drops its reference to the `ImageBitmap`/pixels, so you may `close()` the bitmap right after. Boards still drawing `url` show the placeholder until it is registered again. `false` if `url` was not registered. |
| `setBoard(id, x, y, sceneJson)` | `{ id, nodes, root, ink, layoutMs, paintMs, images, missingFonts, warnings }` | Adds or replaces a board (`sceneJson` is the `/api/scene` text). Layout and scene encoding happen now; textures in `frame()`. A replaced board keeps its old textures as stand-ins until the new ones are drawn. `root` / `ink` are `{x, y, w, h}` in world units. |
| `moveNode(board, id, x, y)` | `bool` | Put a layer at (x, y) in its parent without laying the board out: only when the parent is a frame with layout none and a fixed width and height (nothing else moves with it). The subtree's transforms, hit index and paint follow; shaped text is reused. `false` (nothing changed): set the board instead. |
| `updateNode(board, id, nodeJson)` | `bool` | Replace a layer and its subtree (the node object as the board's scene has it, children included, same ids in the same order) and lay out only that subtree, under the same condition on the parent. For live edits of a few layers (a resize, padding, typed text). `false` (nothing changed): set the board instead. |
| `moveBoard(id, x, y)` | `bool` | Move without a new layout and without rendering: tiles are cut and keyed in board space, so a move only changes where the compositor draws them (snapped to device pixels at rest). |
| `removeBoard(id)` | `bool` | Frees its textures. |
| `raiseBoards(ids)` | `number` | Moves those boards to the top of the paint and hit-test order, in the order given, keeping their layout and textures (no relayout, no placeholder). Returns how many moved. |
| `drawNow(id)` | `bool` | Draw the board whole in the next frame that shows it, whatever the tile budget, and never under the grey placeholder; holds through `setBoard` until every slot of it in view is fresh. For a gesture that hands layers from one board to another (an auto layout drag's overlay and the board it lifts them from): a board left to a later frame showed them twice, nowhere, or under the placeholder. False for an unknown board. |
| `setBoardHidden(id, hidden)` | `bool` | Parks a board (kept laid out, not drawn, hit-tested or in `boardsInView`; its textures age out under the cache budgets) or shows it again. `setBoard` shows it too. Page switches park the boards of the page left. |
| `setCamera(x, y, z)` | — | See coordinates. |
| `resize(cssWidth, cssHeight, dpr)` | — | Call from a `ResizeObserver` and when `devicePixelRatio` changes. Repaints nothing: a new ratio renders tiles of the new scale like a zoom. The tile budget follows the drawing buffer (see `setTextureBudget`). |
| `frame()` | `bool` | Call from `requestAnimationFrame`. Draws only when something changed. Returns `true` while more frames are needed (a gesture is settling, or tiles are still being rendered); keep scheduling frames until it returns `false`, and schedule one after any other call above. The engine measures the display's frame period from consecutive `frame()` calls it asked for, so call it once per display frame while it returns `true`. |
| `redraw()` | `bool` | Draw now, outside `requestAnimationFrame`: right after `resize`, in the ResizeObserver's own task (a resized canvas is cleared, and must not be presented empty). Composites what is cached, renders no tile and stays out of the frame clock. Returns what `frame()` does. |
| `hitTest(screenX, screenY)` | node id or `null` | Topmost node under the point, in paint order, honouring rounded corners, rotation and clipping ancestors. At rest the point goes back through each board's pixel fit, so it is the node whose pixels are there. Like `elementFromPoint(...).closest("[data-id]")` on the DOM board. |
| `nodeRect(id)` | `{x, y, w, h}` or `null` | World-space bounding box (what `getBoundingClientRect() / z` gives on the DOM board). |
| `nodeRectIn(board, id)` | `{x, y, w, h}` or `null` | `nodeRect` looking in that board first (every board when the node is not there). |
| `boardsInView()` | `string[]` | Boards whose ink intersects the viewport. |
| `stats()` | object | Last frame: `frameCpuMs`, `tileRenderMs`, `tilesRendered`, `tileMpx`, `tilesMissing`, `standIns`, `quads`, `gpuDoneMs` (frame start → `onSubmittedWorkDone`, an upper bound), `scale`, `exactScale`; totals: `boards`, `visibleBoards`, `nodes`, `layoutMs`, `paintMs`, `tileCount`, `tileBytes`, `tileBudget`, `images`, `imageLevels`, `imageBytes` (GPU), `imageBudget`, `effectBytes` / `effectBudget` (blur textures), `wasmBytes`, `fonts`; `gpuModel` (`baseMs`, `msPerMpx`: the cost model the tile budget plans with), `shapedTexts` (shaped text layouts kept for boards laid out again, at most 4,096); since the engine started: `tilesWhole` (textures rendered whole), `tilesPartial` (textures brought up to date in place: only the part an edit changed rendered again, or nothing when the edit missed them), `tilesBatched` (of `tilesWhole`, rendered together in a batch), `renderedMpx` (px all those renders covered); `rendererInitMs`, `adapter`, `camera`, `dpr`, `errors`. |
| `memoryReport()` | object | `fontBytes`, `sceneBytes` (vello encodings), `nodes`, `boards`. |
| `setDebug(flags)` | — | `1`: tile borders (red exact scale, blue power-of-two, orange stand-in). `2`: every node's layout box. `4`: render every tile from its board's whole scene, as before per-tile culling (to compare against; every texture renders again when it changes). `8`: render every changed texture whole, as before partial repaints (to compare against). `16`: render every small tile on its own, as before batch renders (to compare against). `32`: a busy GPU, for tests: one tile render a frame, as the cost model plans when other apps keep the GPU busy (`drawNow` boards still render whole). |
| `setBackground(color)` | `bool` | `#RRGGBB` / `#RRGGBBAA` behind the boards. |
| `setTextDefaults(fontSize, lineHeight)` | — | What text without `fontSize` / `lineHeight` inherits. html.ts sets neither, so the DOM board inherits the host page's: the Canvas page body is `13px/1.45`, the default here. `lineHeight` 0 = CSS `normal`. |
| `setTextureBudget(bytes)` | — | GPU texture budget for tiles. Default: 256 MB, or six screenfuls of the drawing buffer when that is more (5K, 6K displays). Once set, it stays. |
| `setImageBudget(bytes)` | — | GPU budget for decoded image levels, default 192 MB. Levels that boards in view draw are never dropped. |
| `setTextDilation(factor, max)` | — | Calibration: the macOS font-smoothing dilation, `factor` device px per ppem capped at `max` device px (defaults 0.006 / 0.3, fitted to Chrome screenshots). Every texture renders again. |

### Shader cards

Free-standing cards that run a WGSL fragment shader (`fn shade(p: vec2<f32>) -> vec4<f32>`, premultiplied output; contract and checks in `src/shaders.rs`). Their textures live outside the tile cache and are composited above every board, in card order, with rounded corners. The page side is `src/page/shaders.js`.

| Call | Returns | Notes |
|---|---|---|
| `setShaderCard(id, x, y, w, h, order, play, radius)` | — | Add or move a card (world units). `play`: autoplay; a hovered card plays either way. |
| `setShaderSource(id, wgsl)` | `Promise<{ok, errors:[{line,col,message}], stale?, unchanged?}>` | Our checks first (nothing banned reaches the GPU), then an async compile. The last good pipeline keeps running until a new one compiles. A compile overtaken by a newer source resolves `stale`. |
| `setShaderParams(id, Float32Array)` | `bool` | `u.params` (32 vec4, 128 floats; missing and non-finite ones are 0). No compile: a playing card uses them next frame, a still card redraws its still. Paper preset cards keep their uniforms here (src/paper.ts). The wrapper also binds Paper's noise texture, read with `canvas_noise(uv)`. |
| `removeShader(id)` | `bool` | |
| `setShaderHover(id, x, y, pressed)` | — | Card px; `""` clears. Hovered: 60 fps, outside the budget up to 8 ms. |
| `setShadersRunning(visible, autoplay)` | — | Hidden window: nothing plays. Reduce Motion: `autoplay` false, hover still plays. |
| `setShaderSnapshot(on)` | — | Every visible card shows its frame at t = 2 s (freeze uses it). |
| `setShaderPoster(id, imageBitmap)` | `bool` | Show a cached poster PNG until the card plays. |
| `renderShaderFrame(id, t, maxSide, read)` | `Promise<{width, height, msPerFrame, msPerMpx, pixels?}>` | Offscreen frame; `pixels` straight-alpha RGBA8. Timing is an onSubmittedWorkDone latency estimate (vello's device has no timestamp-query feature). |
| `shaderWakeMs()` | ms or -1 | When the next playing card is due; the page sleeps until then. |
| `shaderStats()` | object | Per card: status, errors, playing, msPerMpx, texture, shows, renders; frame: rendered, posters, playing, predictedMs, budget, texture bytes. |

Policy: at most 4 cards play (largest on screen first, the hovered one counts), within 4 ms predicted GPU per frame, at 30 fps on one shared tick (60 hovered). Cost per card comes from a probe (three frames at 256 px, again at 768 px when that was light, re-probed while high; the lowest reading is kept). Texture: card size x zoom x dpr, long side at most 1024 (512 mid-gesture), 15% hysteresis, all cards inside 64 MB. A card that is not playing shows one frame at t = 2 s.

### Video cards

Same list, admission, budget, deadlines and quads as shader cards (the 4-card cap and 4 ms budget count both kinds). Frames come from an `HTMLVideoElement` the page owns (`src/page/videos.js`): the engine plays and pauses it with the admission, and when the video's time moved it wraps the current frame in a `VideoFrame` (skipped if the element has none), copies it into a staging texture at the video's own size (shared per size, dropped after 2 s unused) and filters it (box of up to 6x6 bilinear taps) into the card texture at its on-screen size, cropped like `object-fit: cover`. Cost model: 0.05 ms + copy ms/Mpx x decoded Mpx (0.08 default; the lowest measurement, kept within 1x-4x) + filter. Posters (`setShaderPoster`) are cropped the same way. `shaderStats()` cards carry `kind`, `native`, and the frame `videoCopyMsPerMpx`, `stagingBytes`, `videoUploads`.

| Call | Returns | Notes |
|---|---|---|
| `setVideoCard(id, x, y, w, h, order, play, radius)` | — | Add or move a video card. `play`: autoplay (and not paused by the person). |
| `setVideoElement(id, el \| null)` | `bool` | The element to draw from; the same element again is a no-op. |
| `setVideoForced(id, on)` | `bool` | The person pressed play: first in line like a hovered card, while on screen. |
| `wantVideoFrame(id)` | `bool` | Draw the element's current frame on a still card (after a seek or scrub). |
| `removeShader(id)`, `setShaderHover(...)`, `setShaderPoster(...)` | | Work for video cards too. |

### Typical loop

```js
let raf = 0;
const kick = () => { if (!raf) raf = requestAnimationFrame(() => { raf = 0; if (engine.frame()) kick(); }); };
new ResizeObserver(() => { engine.resize(canvas.clientWidth, canvas.clientHeight, devicePixelRatio); if (engine.redraw()) kick(); }).observe(canvas);

const scene = await (await fetch(`/api/scene?file=${f}&id=${id}`)).json();
for (const font of scene.fonts) { // in order: tagged faces chain in it
  const r = await fetch(font.url);
  if (r.ok) engine.registerFont(font.family, +r.headers.get('x-font-weight') || 0, r.headers.get('x-font-style') || '', new Uint8Array(await r.arrayBuffer()));
}
engine.setBoard(id, meta.x, meta.y, JSON.stringify(scene));
for (const url of scene.images) createImageBitmap(await (await fetch(url)).blob()).then((bm) => { engine.registerImage(url, bm, bm.width, bm.height); kick(); }); // keep bm open
engine.setCamera(cam.x, cam.y, cam.z);
kick();
```

## How it draws

- Each board is laid out (taffy + parley) and encoded once into a vello scene in board coordinates; it is re-encoded only when the board, its fonts, its images or the resolution its images are drawn at change. Text layouts are freed after encoding (the scene holds the glyphs) and shaped again for the next paint.
- Text: variable fonts follow `wght` and `opsz` (= font size in px, as Chrome's `font-optical-sizing: auto`). Glyphs get the outward dilation macOS font smoothing gives them (0.006 device px per ppem, at most 0.3, none above 72 ppem), sized per render for the device px they land at, zoom included, as Chrome does.
- Blur: layer blur, background blur, drop shadows on text/paths/icons, and box shadows with per-corner radii or ellipses are rendered as effect jobs: the content goes to an offscreen texture at about 2.5 texels per σ, gets a separable Gaussian on the GPU, and is drawn back as an image. Uniform-radius box shadows use vello's analytic blurred rounded rect.
- Boards are drawn into textures and composited as quads, sampled premultiplied (manual filtering on premultiplied texels, so transparent texels add no dark fringe). A texture drawn smaller than 1:1 is box-filtered over each pixel's exact footprint (up to 10 x 10 texels), not sampled with four taps, so fine text and hairlines do not shimmer mid-zoom. Every texture carries a 2 px gutter of the board's real content, so filtering at a tile edge reads its neighbour instead of clamping.
- A tile renders only the part of its board's scene that meets it (`cull.rs`: the scene is indexed as items with bounds while it is painted). vello's GPU buffers have a fixed size (2^21 lines, 2^18 bin words, ...) and a scene over them renders as nothing, silently; a tile whose own content would still overflow is rendered in parts (halves of halves, down to 16 px) and copied together, as many parts a frame as the budget admits: the job carries over to the next frames and the slot keeps its stand-in until the last part is in. A tile no split makes drawable is not cached: the slot keeps its stand-in, `stats().errors` names the board, and `stats().tileWork.failed` counts such slots. `stats().tileWork` also has `parts` (vello renders the frame's tiles took), `ahead` (tiles rendered ahead of the view), `framePeriodMs` and `panPerFrame`.
- Tiles ahead of the view render after everything the view shows: half a tile around a view at rest, and up to three tiles in the direction of a pan (twelve frames of its speed), while the tile cache is under 80% of its budget; over it, textures of other scales and older generations (never a base texture) make way for them first. A tile ahead of the view is done once it holds the board's current content. One that shows an image below the level its scale needs (an image is tiled only in view) is kept as low resolution and drawn again when it comes into view.
- While the zoom changes, textures render at power-of-two scales. When the level above the scale on screen is affordable (the GPU's tile share renders four times the view within a second of frames, and it fits 70% of the tile budget), it renders as soon as the scale passes a power of two, inside the frame budgets, and is minified on screen: text stays sharp through a pinch. When it is not, the level below is kept while it is stretched by at most 1.2x. Decided once per gesture.
- At rest every board is fitted to whole device pixels: each edge of its frame lands on the device pixel nearest to where the world puts it, so boards that share an edge in the world share it on screen (no gap, no overlap). The frame is then a whole number of pixels wide, and the board is rendered that fraction of a pixel wider or narrower (not resampled). A board whose ink reaches more than two frame sizes from its origin (content far outside a small unclipped frame) is not stretched: only its origin snaps. Such tiles have their own key (`ScaleKey::Fitted`), so a board dragged at a zoom where its size is not whole pixels renders each of at most four variants once. A slot without a fresh texture shows stand-in pieces: the best cached scale first (finer is preferred, older generations only where nothing current covers), then coarser scales for whatever is still uncovered, each piece scissored to its own part of the slot (pixel-centre rule, so no pixel is drawn twice or skipped), and a placeholder only where nothing is cached. Every board near the view also keeps a base texture (its whole ink at the power of two that fits 512 px, or less on a crowded view: see below), rendered once and evicted last, so a fast pan or a pinch out shows a soft picture instead of a hole. During a gesture slots with nothing (or a stand-in over 2x too coarse, or old content) render first, a current stand-in up to 4x finer is kept, and the work per frame is capped by CPU time and by the GPU time a cost model fed from `onSubmittedWorkDone` predicts, both shares of the display's frame period measured from the frames themselves (mid-gesture 36% and 24% of it: 6 ms and 4 ms at 60 Hz, 3 ms and 2 ms at 120 Hz; settled 60%: 10 ms at 60 Hz). The GPU share is for tiles: the composite's own measured time is added to it, up to three quarters of the period. Effect jobs render only for the tiles that show them, one admission each, and their textures sit in a 128 MB LRU (`effectBudget`). Image levels are not raised mid-gesture; a tile drawn with lower levels is drawn again once the camera settles. 150 ms after the camera stops (or any time the zoom is unchanged, e.g. a pan), textures render at the exact scale, nearest the centre first, and land on whole device pixels (one shift per board, so tiles meet without a gap). Exact tiles that replace current stand-ins of another scale are revealed together once the last one is ready (at most 250 ms after the settle), so the view sharpens in one step instead of tile by tile; edits appear at once. Every board's image levels together stay within 24 Mpx (vello's image atlas is 8192² and silently drops images that do not fit), and the atlas is flushed when three consecutive renders could overflow it.
- A board up to 2400 device px on both sides at that scale is one texture; a bigger one is cut into 1024 px tiles and only visible tiles render. Boards and tiles outside the viewport are culled.
- An edit repaints only what it changed. Every new generation of a board notes the region it changed (board space): `moveNode` and `updateNode` the union of what the subtree drew before and draws now, a `setBoard` that replaces a board with the same layers in the same order the union over the layers whose properties, place or ink differ (`board::replaced_dirty`). A texture of an older generation then renders only that region again, on vello's 16 px grid, into the texture in place (`Gpu::render_into`; a region over 60 % of it renders whole). A change whose reach is unknown (a whole repaint, new fonts, layers added or removed, the root itself, anything an effect job reads: a backdrop or layer blur) renders whole, as does a texture older than the 32 generations the log keeps. Exact tiles and base textures take it; a gesture's tiles and a tile whose images are below their level render whole. Pixel-checked by `bench/dirty-check.ts` against a fresh open: a resize renders 0.11 Mpx per move instead of 1.69 on a phone board at 100 % (2x).
- Small tiles render in batches. A tile up to 384 x 384 device px that renders in one part (an overview's boards, base textures, small tiles ahead of the view) joins the frame's batch: its part of its board's scene goes into a cell of a 2048 px scratch atlas, clipped to the cell, and after the frame's other work one vello render draws them all and each cell is copied into a texture of its own (`Gpu::render_batch`). The batch's first tile is admitted like any render; the rest join under the CPU budget alone (the render they add to is admitted already), while the cells fit the atlas, their summed estimates vello's buffers and their boards' images the image atlas. Same pixels as rendering each alone (`bench/batch-check.ts`). An overview of 200 boards renders its 400 textures in a frame or two instead of one a frame on a busy GPU.
- Base textures fit their share. Their long side follows how many boards are near the view: 512 px, halved while all of them together would take over 30 % of the tile budget (down to 64 px), doubled back once twice the size would take under a third of that. They wait until no board was added for 400 ms, since each step renders them all again.
- Textures sit in an LRU under the budget; stale generations and other scales go first; nothing used in the current frame is evicted.

### Board motion

- `setBoardTransform(id, a, b, c, d, e, f, alpha)` sets a world-space affine and compositing opacity. It leaves the scene, layout and tile generations intact. Identity with alpha 1 clears the transform. Returns false for an unknown board or invalid values.
- `setBoardSprite(id, owner, clip)` makes an existing board a transient sprite. It paints after the owner, skips hit testing and uses the optional world-space clip `[x, y, width, height]`. Pass a Float64Array with no entries for no clip. Place the sprite at the owner's origin before hiding its layer so both use the owner's static pixel grid. Use `drawNow` when handing layers between the owner and its sprites, then `removeBoard` to drop the sprites.
- `spriteFrame()` returns the last display frame number that composited a sprite tile successfully, or 0 before the first one.
- `nodeInkIn(board, id)` returns subtree paint bounds in world coordinates. `nodeMotionRect(board, id)` returns the layout size at the node's world origin. `boardAt(x, y)` picks a board by its resting bounds in canvas-relative CSS coordinates. `textureBudget()` returns the tile cache limit in bytes.
